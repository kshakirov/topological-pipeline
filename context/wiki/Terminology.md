# Терминология Topological Pipeline

Эта страница фиксирует словарь проекта: какой термин мы используем, какую семантику он обещает и где название пока остаётся исследовательским.

Главное правило: имя должно описывать наблюдаемое поведение компонента. Термины CSP используем в смысле Хоара; проектные метафоры не должны незаметно менять их значение.

## Принятые термины

### Parallel Node

Единый топологический узел с внутренней степенью параллелизма `n`:

```text
External Input
      |
      v
 Dispatcher
  /   |   \
 W1  W2  ... Wn
  \   |   /
      v
   Smoother
      |
      v
External Output
```

Количество workers меняет внутреннюю физику исполнения, но не внешний контракт узла. В перспективе это аналог `Bolt` в Storm.

### Worker

Независимый вычислительный процесс внутри `Parallel Node`. Worker получает квант через собственный вход, применяет функцию и отправляет результат в общий выходной контур. Workers не владеют общим изменяемым состоянием.

### Box

Контейнер пользовательского вычисления. `Box` описывает вычислительную функцию, а `Worker` — исполняющий её процесс. Эти понятия не считаются взаимозаменяемыми.

### Round-Robin

Детерминированная политика диспетчеризации:

```text
next = (current + 1) mod n
```

В текущем эксперименте это **next worker**, а не **next available worker**. Если назначенный worker не готов, диспетчер блокируется даже при готовности другого.

### Parallel Composition

Композиция независимых workers, исполняющихся конкурентно. Проект использует обозначение CSP `||`, когда синхронизация по общим событиям существенна для модели.

### Interleaving

Наблюдаемый порядок событий от конкурентных workers без обещания восстановить исходный входной порядок. Для чистого чередования используется обозначение CSP `|||`.

Interleaving — семантика потока, а не название алгоритма сортировки.

### Smoother

Внутренняя выходная часть `Parallel Node`, принимающая результаты workers и превращающая конкурентные отправки в один последовательный поток наблюдения.

Smoother фиксирует порядок прихода. Он не восстанавливает исходный порядок входов и не становится самостоятельным топологическим узлом.

### Buffer Process

Процесс — единственный владелец изменяемого среза результатов. Только он выполняет `append`. Наличие `single writer` ещё не определяет, где находится `single observation point`; протокол выдачи окончательного результата фиксируется отдельно.

### Backpressure

Свойство протокола передачи, при котором медленный downstream ограничивает upstream. В локальном макете оно моделируется блокирующими unbuffered channels; в распределённом варианте должно стать свойством `Wire`.

### Wire

Транспортный контракт между внешними топологическими узлами. Go channel — текущая локальная модель транспорта, но не окончательное определение `Wire`.

## Термины, требующие точного решения

### External Choice

В CSP внешний выбор `P □ Q` разрешается первым событием, которое предлагает окружение. Текущий диспетчер выбирает worker по внутреннему индексу Round-Robin, а не по готовности внешнего события.

Поэтому имя `LocalExternalChoice` пока считаем гипотезой. Возможные более буквальные имена:

- `RoundRobinDispatcher`;
- `CyclicDispatcher`;
- `LocalDistributor`.

Окончательное имя принимается после формализации алфавита событий компонента.

### Total Order

Один потребитель канала задаёт линейный порядок наблюдения результатов. Это total order фактического прихода, но не реконструкция причинного или исходного порядка сообщений.

## Кандидаты на уточнение имён в коде

Это не список обязательных переименований, а очередь семантических вопросов.

| Сейчас | Вопрос | Возможное направление |
|---|---|---|
| `LocalSplitNode` | Снаружи это split или целый parallel node вместе со smoother? | `LocalParallelNode` |
| `LocalExternalChoice` | Есть ли здесь CSP external choice или только Round-Robin? | `RoundRobinDispatcher` |
| `WriteWithChoice` | Метод пишет, выбирает или непрерывно диспетчеризует? | `Dispatch` / `Run` |
| `LocalSplitBuffer` | Это пассивный buffer или автономный process/smoother? | `LocalSmoother` / `BufferProcess` |
| `Interleave` | Это операция над одним значением или жизненный цикл процесса? | `Run` / `Collect` |
| `Node` | Это внешний узел графа или внутренний worker? | `Worker` |
| `BoxB` / `BoxFuncB` | Что означает суффикс `B` в контракте? | Уточнить тип кванта либо убрать временный суффикс |
| `Dump` | Допустима ли прямая мутация в обход владельца? | Удалить после закрепления канального входа |
| `InChan` / `OutChan` | Имя фиксирует реализацию вместо роли порта? | `In` / `Out` после стабилизации контракта |

## Правило принятия имени

Перед переименованием отвечаем на три вопроса:

1. Какое наблюдаемое поведение обещает имя?
2. Совпадает ли оно с формальным термином, если термин заимствован из CSP?
3. Сохранится ли смысл после замены локального channel на распределённый `Wire`?

Если ответы ещё не установлены экспериментом, имя остаётся рабочим и помечается здесь как гипотеза.
