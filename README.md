# Манифест архитектуры Topological Pipeline (V6.0)

## 1. Декларация принципов

Настоящий документ фиксирует базовую физику и инварианты распределенной системы потоковой обработки данных с нулевым оверхедом (Zero-Overhead Streaming Engine). Назначение манифеста — сохранение архитектурной непрерывности графа вычислений при любых деструктивных воздействиях на среду исполнения или память оператора.

Система базируется на трех фундаментальных законах:
1. **Изоляция вычислений от транспорта**: Вычислительный узел не имеет права знать физическую природу и топологию каналов связи.
2. **Явная внешняя коммутация**: Маршрутизация, слияние и разделение потоков выносятся наружу как самостоятельные аппаратные единицы. Внутри узлов обработки логика ветвления запрещена.
3. **Честное обратное давление (Backpressure)**: Конвейер регулирует скорость источника по Pull-принципу, используя блокирующие Push-акты в шинах данных. Память процесса не должна расти при замедлении узлов.

## 2. Анатомия компонентов конвейера

### 2.1 Квант данных (Set / Tuple)
Минимальная неделимая единица информации в конвейере. Не имеет жесткой номинативной привязки. Проходит сквозь граф как абстрактное множество, раскрывающееся внутри вычислительных узлов через механизмы структурной субтипизации.

### 2.2 Двухтактный ящик (ComputeNode)
Монолитный изолированный операционный автомат, реализующий чистые функции бизнес-логики. Внутри узла отсутствует промежуточная буферизация.
* **Такт IN (InBox)**: Захват кванта данных из входного интерфейса, выполнение первичных мутаций.
* **Такт OUT (OutBox)**: Прием промежуточного состояния через внутренний шлюз и генерация финального выхлопа в исходящий провод.

### 2.3 Активный провод (Wire)
Транспортный диспетчер, реализующий паттерн инверсии управления (Inversion of Control). Во избежание утраты аппаратного недетерминизма встроенного оператора `select` рантайма Go, провод инкапсулирует асинхронные циклы и горутины внутри себя.
* Принимает абстрактный оператор вычисления (`Processor/Callback`) на вход.
* Самостоятельно управляет чтением из подлежащей среды (локальная память, сетевой сокет, gRPC-поток).
* Блокирует поток управления при переполнении буфера приемника, обеспечивая децентрализованный Backpressure.

### 2.4 Внешняя коммутация (MuxNode / DemuxNode)
Микросхемы явного сопряжения графа. Выполняют функции мультиплексирования (слияния) и демультиплексирования (маршрутизации по ключу/хешу) на абстрактных проводах вне зоны ответственности вычислительных ящиков.

## 3. Алгоритм развертывания топологии

Конвейер собирается динамически на основе декларативной конфигурации (YAML). Процесс сборки разделен на четыре дискретных шага:
1. **Синтаксический анализ**: Парсинг статической карты связей графа в структуры метаданных.
2. **Аллокация шин**: Нарезка и инициализация интерфейсных абстрактных проводов с заданным уровнем параллелизма и емкости буферов.
3. **Регистрация контрактов**: Передача вычислительных узлов в методы инверсии управления соответствующих проводов.
4. **Запуск автоматов**: Активация горутин внутри проводов, перевод системы в рабочий режим непрерывной потоковой обработки.

---

## 4. Критические инварианты для восстановления

Если контекст потерян, восстановление системы производить строго по следующим точкам проверки:
* Проверить, что `ComputeNode` не содержит внутри себя циклов `for range` по явным каналам `chan`. Если каналы внутри ящика обнаружены — архитектура деградировала к монолиту. Вынести циклы в `Wire`.
* Проверить, что типы данных связываются через структурные интерфейсы, а не через жесткие дженерик-контракты в рантайме, блокирующие динамический парсинг конфигурации.
* Проверить, что граф является строго направленным ациклическим графом (DAG). Наличие неявных петель обратной связи без выделенных координирующих автоматов ведет к распределенному дедлоку.
